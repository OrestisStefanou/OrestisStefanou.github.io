An investment analyst that runs on your own machine.

InvestPal is a self-hosted, single-user investment advisor built on the Model Context Protocol. Five MCP servers put keyless market data, fifteen value-investing skills and, optionally, your own brokerage accounts in front of Claude. Your profile, notes and history stay in one SQLite file on your laptop.

Install 
$ git clone https://github.com/OrestisStefanou/InvestPalEcosystem
$ cd InvestPalEcosystem
$ make setup

That is the whole thing. make setup checks prerequisites, clones the five service repos, installs their dependencies, writes your configuration, prepares the database and search index, and starts everything. No API key required: in the Claude Code cockpit, Claude Code is the LLM.

What it is

Three things it does differently.

InvestPal is not a hosted chatbot with a market-data plugin. It is a set of MCP servers you run yourself, a database you own, and a written methodology the agent is required to follow.

Your portfolio never leaves the room.

There is no hosted backend, no account, no auth and no tenancy. Setup creates a single turso/SQLite file on your machine, and your profile, conversation notes, reminders and workflow results all live inside it.

  • Embeddings are computed on your own CPU with BAAI/bge-small-en-v1.5. Note text is never sent anywhere.
  • Brokerage credentials travel as per-request headers and are never stored.
  • .env.secrets is mode 600 and denied to the agent by the cockpit's permission rules.
  • Turso Cloud sync exists and is entirely opt-in and manual. Nothing syncs on startup, on shutdown, or on a timer.
investpal.db
One SQLite file with native vector search, created on first start. No database server to run.
EMBEDDING_ENABLED
Set it to false and semantic search over your notes is switched off entirely.
ALPACA_READ_ONLY · COINBASE_READ_ONLY · IB_READ_ONLY
Each hides every order-placing tool from the advisor, so it can read a portfolio but cannot act on it.

Fifteen procedures instead of an opinion.

Skills are step-by-step analytical procedures that encode a methodology: Graham & Dodd on valuation, Howard Marks on cycles and second-level thinking. They are plain Python in the repository, so you can read exactly what the model was told before it answered you.

  • “Always prefer a skill over ad-hoc analysis” is in the advisor's own prompt.
  • So is the line “skipping a relevant skill is a defect.”
  • Answers adapt to a declared knowledge level: beginner, intermediate or advanced.
  • The same procedures run unattended inside scheduled workflows.
getSkillDefinitions
Lists every skill with a one-line summary of what it is and when to reach for it.
getSkill
Returns the full written procedure for the agent to work through, step by step.
Lineage
Graham & Dodd's Security Analysis for valuation; Howard Marks' The Most Important Thing for cycles, sentiment and second-level thinking.

Five servers, four front-ends, one protocol.

Every capability is an MCP tool, and nothing is hard-wired to a particular client. The same toolset drives the Claude Code cockpit, Claude Desktop, a browser console and anything you build yourself on the REST API.

  • Market data is a standalone Go server; each broker is a standalone Python server.
  • Adding a broker means adding a server, not rewriting the agent.
  • The core exposes a REST API on :8000 and its own MCP app on :9000.
  • Claude Code and Claude Desktop connect straight to the MCP servers, bypassing the REST layer.

Skills

A written methodology, not a personality.

Fifteen analytical procedures the advisor is required to follow. They are the difference between an answer and a defensible answer.

analyze_balance_sheet

Liquidity, solvency, asset quality and capital structure, read against the company's sector profile.

analyze_cash_flow

Operating and free cash flow, cash quality, and the maintenance-versus-growth CapEx gap that reveals owner earnings.

analyze_earnings_quality

Eight dimensions, from cash conversion to tax quality, testing whether reported earnings are real.

analyze_income_statement

Sustainable operating income via 7–15 year margin averaging, plus pricing power and hidden growth spend.

analyze_macro_impact

Whether current earnings sit above or below sustainable levels, and what that does to the cost of capital.

analyze_management_commentary

Guidance architecture, tone shifts, and the gap between stated priorities and actual capital allocation.

analyze_portfolio_risk

Aggregate risk of permanent capital loss across eight dimensions, including hidden correlations and forced-selling exposure.

analyze_stock_valuation

Whether the price on offer is a good purchase, a separate question from whether it is a good business.

apply_second_level_thinking

A nine-point stress test of a thesis against consensus, looking for informational, analytical, behavioural or structural edge.

assess_competitive_moat

Franchise or commodity business, decided by comparing earnings power value against asset value.

assess_market_sentiment

A 22-item heated-versus-cold checklist across the economic cycle, the credit cycle and investor psychology.

calculate_intrinsic_value

Graham & Dodd in three elements: asset value, earnings power value, and growth value only where a franchise exists.

compare_sector_peers

Three to six peers ranked on growth, profitability, valuation multiples and balance sheet health.

evaluate_investment_theme

Turns a theme into a falsifiable claim, then finds which link in the value chain actually captures the economics.

evaluate_margin_of_safety

Defensive-investing discipline applied to a single position or a proposed trade.

Two tools expose the skills to the agent: getSkillDefinitions to see what exists, and getSkill to read the full procedure. You can inspect exactly the reasoning the advisor was asked to perform.

Brokerages

all optional
  • Alpaca · 6 tools
  • Coinbase · 5 tools
  • Interactive Brokers · 14 tools

Read accounts, positions, balances, orders and trade history. Alpaca points at the paper endpoint by default and live trading needs an explicit override. Setting the relevant READ_ONLY flag hides every order-placing tool. Interactive Brokers never accepts a trading warning on your behalf: placeOrder returns NEEDS_CONFIRMATION with a reply_id, and the order stays off the market until confirmOrder is called.

You do not need an Alpaca, Coinbase or Interactive Brokers account. InvestPal is fully functional as a conversational research tool on market data alone. Brokerage integrations are optional, off by default, and can be run read-only.

Architecture

Five services, all on localhost.

Clients talk to the core over REST, or straight to the MCP servers. The core orchestrates the servers on behalf of anything that cannot speak MCP itself.

InvestmentManagerAgent

The user-facing advisor. Holds the persona, reaches for skills, calls the market-data and brokerage tools.

UserContextMemoryManagerAgent

Writes long-term memory in the background on a cheaper model, so the conversation is never interrupted to take notes.

WorkflowExecutionAgent

Non-conversational. Runs scheduled workflows when they come due and stores the report.

Get started

One command, then a conversation.

Terminal 
$ git clone https://github.com/OrestisStefanou/InvestPalEcosystem
$ cd InvestPalEcosystem
$ make setup
$ make claude

Prerequisites

  • git
  • make
  • curl
  • nc
  • Go 1.25+
  • uv
  • Java 1.8+ (Interactive Brokers only)

make setup checks all of these and tells you what is missing. make doctor confirms the services are healthy afterwards.

  1. Run setup

    It checks prerequisites, clones the five service repositories, installs their dependencies, writes your configuration, prepares the database and search index, and starts everything.

  2. Answer three optional questions

    Whether to enable InvestPal's own backend agent, and whether to connect Alpaca and Coinbase. All three default to no and all three can be skipped with Enter, or with make setup YES=1.

  3. Open the cockpit

    make claude starts Claude Code as the advisor. It loads the persona, picks up your profile and runs any workflows that are due.

  4. Re-run it whenever

    make setup only does what is still missing. make setup FORCE=1 reconfigures from scratch, and make pull updates the service repos.

Run it yourself. Read every line.

InvestPal is a personal project, built in the open, and it runs entirely on your machine.
